# 账号注销

设置 → 账号管理 → 注销账号，输入当前密码确认。无需新增环境变量。

`POST /api/auth/delete-account` 接收 `{ "password": "当前密码" }`，用户身份只取自有效 Cookie/Bearer 会话。成功返回 `{ "ok": true }`；密码错误为 403，同账号 15 分钟最多 5 次错误，另有 IP 限流。数据库事务删除用户及关联业务、同步文档、刷新凭据和邮箱注册验证码，成功提交后才清 Cookie。事务失败整体回滚。

迁移 `202610220001_account_deletion.sql` 增加密码尝试限流表，并修复用户级联删除时同步版本触发器重建孤立状态行的问题。先发布 API 并确认迁移，再发布 Web。有效旧 access token 可重复提交注销以确认丢失的响应；原账号凭据不会影响同邮箱重新注册的新 user ID。有效旧访问或刷新凭据访问已注销账号时返回 `410` 与 `code: "ACCOUNT_DELETED"`。

客户端先暂停计时、等待同步和本机写入结束，再请求注销。密码错误恢复操作，超时保留本机数据并暂停写入，直到重试确认结果。确认删除后清理当前 API/用户的主记录、逻辑备份、计时、身份与 Token，压缩本地数据库并更新恢复快照。持久删除标记阻止陈旧写入重新持久化数据；重启会继续清理。其他设备在联网识别账号已注销后清理本机缓存，离线设备无法即时清理。

无法解析的历史损坏文件会显示具体路径，需用户逐个手动处理，以免破坏同设备其他账号的数据。用户已导出的 JSON 由用户自行保管。服务器历史数据库备份按既有保留策略管理；注销删除当前业务数据库中的数据，恢复历史备份时须防止重新引入已注销账号。

验证包括 PostgreSQL 的完整删除、错误密码、事务回滚、重复请求、刷新/同步并发，以及 Flutter 的离线保留、暂停写入、远端注销、缓存隔离、备份清理、重启重试和确认弹窗。
